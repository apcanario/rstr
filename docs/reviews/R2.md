## Should-fix

**S1. Nothing fails when a palette forces designs onto fallbacks.**
- File: `tests/proof.test.ts:40-46` (the "every palette picked, in both modes" suite) and `tools/smoke.py:24-31, 39-44`.
- Failure: a candidate passes only if rule 4 holds for all 16 forms of the style (`src/engine/layout.ts:58-76`). One form that fails a candidate the others pass removes that candidate for every palette and mode; if no candidate survives, the design falls back. The fallback passes 9.2, so the tests stay green while every design of the style collapses to the fallback frame. Today the count is 0 on every unpicked and per-palette run, but nothing holds it there; the same coupling is why a new palette (R11 My palettes) can quietly cut the variety of a whole style.
- Fix: in the per-palette and unpicked 9.2 suites assert `r.fallbacks === 0` (unit tests and smoke), keeping the picked-run counts as they are with a recorded ceiling (Vaporwave 1:1 picked 196 of 800 today). Print the spec of any unexpected fallback.
