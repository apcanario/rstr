## Should-fix

**S1. Finish and Marks controls do nothing yet.** `src/app/App.tsx:342`, `:345`; `src/engine/finish.ts:5`. Grain, Grunge, VHS, Glitch, Light and Full each change the spec and use up a Back step, but they draw nothing until R7. R7's row says it builds "the Look tab's Finish and Marks controls". Seen at 360 x 640, Look page 1: tap Grain and the stage does not change. Fix: until R7, render the non-Clean finishes and the non-Off marks as disabled, or leave Finish and Marks off the Look tab and let R7 add them. If they are hidden, the Look tab becomes Light/Dark plus the rerolls on one page.

**S2. A `?s=` link silently replaces the saved design.** `src/app/App.tsx:74-79`. `load()` overwrites `saved.spec` with `migrate(q)` and does not push the design that was there onto Back. Opening a shared link therefore loses the current design, including its typed text, with no way back. A malformed link also replaces it: `migrate` returns `defaultSpec()` with seeds 1, 2, 3, 4 instead of failing. Fix: when the link is present, `saved.back = pushBack(saved.back, saved.spec)` before replacing. If `q` does not parse as an object (test `JSON.parse` inside a try), keep the saved design and ignore the link. Add both cases to `appcheck.py` (open with `?s=` over a saved state, then Back; open with `?s=garbage`).

**S3. Autosave failure is silent.** `src/app/App.tsx:257` and `:72`. When `setItem` throws (quota or private mode), the design, Back steps and Kept are not saved and nothing tells Pedro. Spec 10.1 promises they return on reload. Fix: on a caught failure, set the existing `note` line (or a header flash) to "Not saved on this phone: storage full". On the first failure, retry once without `back`. Add a smoke step that stubs `localStorage.setItem` to throw and checks the note.

**S4. Saved Kept beyond 500 drops the newest designs.** `src/app/state.ts:72`, `:78`. `keep()` puts new designs first (`[s, ...k]`, `App.tsx:182`), but `restore` keeps `x.slice(-max)`, which is the oldest 500. Back is newest-last, so `slice(-30)` is right for Back, and the same helper is wrong for Kept. Also, `keep()` is unbounded, so the in-memory list and the saved list disagree past 500. Fix: `kept: Array.isArray(r.kept) ? r.kept.slice(0, 500).map(migrate) : []`, and cap in `keep()` with `.slice(0, 500)`. Add a unit test with 510 kept specs that checks the first one survives.

**S5. Text tab is split into two pages even where four rows fit.** `src/app/App.tsx:338`; `src/app/app.css:38`. Pages are hardcoded, and the panel is capped at 168 px. At 412 x 915 the stage takes about 490 px, yet Title and Subtitle sit on page 1 and Info and Caption on page 2, behind chips (`screen-412x915-text-1.png`, `-text-2.png`). Spec 10.1 says "page chips when they do not fit", and `ui-2-text.jpg` shows the four rows on one panel. The same applies to Look. Fix: give the panel a height from the viewport, for example `clamp(114px, 26dvh, 228px)`. Build the pages from how many 48 px rows fit, either measured in a layout effect or by a breakpoint on `innerHeight` (four rows from about 760 px). Add an appcheck assertion that the Text tab has no chips at 412 x 915.

**S6. The reroll buttons read as a second row of locks.** `src/app/App.tsx:348`. Visible labels are "Layout, Colour, Graphic, Type", the same words as the locks directly above (`screen-360x640-look-2.png`). Spec 10.2 names them "New layout, New colours, New graphic, New type". Fix: caption the row "New" the way Marks is captioned (`<div class="captioned"><L t="New" c="cap"/>…`). Alternatively, label each button `REROLL_LABEL[f]` and let `fit` shrink it.

**S7. The layout check cannot see the panel spilling into the action row.** `tools/appcheck.py:21-56`. Overflow of a fixed-height box into its neighbour is neither scrolling nor off screen. Fix: in `LAYOUT_JS`, assert that every shown descendant of `.panel`, `.locks`, `.actions`, `header` and `.sheet` lies inside its container's rect. Also assert that the frame's seven parts do not overlap one another.

## Minor

**M1. "Longest" is by character count.** `tools/appcheck.py:109-110`. Rendered width is what matters. "Schibsted Grotesk" (17 characters) is shortened at 360 x 640, while names with more characters fit. Fix: pick the longest by `measureText` width in DM Sans 11 px through `page.evaluate`, or run the layout check once per pairing and palette (the probe above takes seconds).

**M2. A label shortened to "…" alone passes.** `tools/appcheck.py:54`. Fix: fail when a shortened label keeps fewer than 4 characters before the "…".

**M3. Lock tests set hand picks for Colour and Type only.** `tools/appcheck.py:200-203`; `tests/app.test.ts:21-22`. Layout and Graphic locks with `pick.layout` or `pick.motif` set are never exercised. `shuffle()` is generic, so this is low risk. Fix: set `pick.layout` and `pick.motif` in the unit test as well.

**M4. The Advanced switch label shows the current state as a plain button.** `src/app/App.tsx:361`. A button reading "Simple" that turns into "Advanced" when tapped reads as a command, and in R4 Advanced changes nothing visible. Fix: label it "Advanced" always, with the on state given by the existing `aria-pressed` edge, or use a two-segment Simple|Advanced control.

**M5. The selected style tile does not show the current design.** `src/app/App.tsx:279`. `withStyle(spec, id)` clears the picks even for the current style, so a design with a picked motif or palette shows a different poster in its own tile. Seen at both sizes: the stage draws Topo while the Swiss tile draws dots (`screen-*-style-1.png`). Fix: `const s = id === spec.style ? spec : withStyle(spec, id)`.

**M6. Pairing names are shortened on the Type lock.** This is legal but clumsy. The lock value is 11 px in a quarter-width button. At 360 x 640, swiss/pomo/brutal/vapor with `pick.pairing` set to the Rubik Mono / Cormorant pairing shows "Rubik Mono / C…", and 8 of 42 names are shortened. At 412 x 915, 4 are shortened. Fix: show only the display family on the lock (`name.split(' / ')[0]`) and keep the full name for the Type tab in R10.

**M7. Each change on the Style tab renders four full-size posters for the tiles, on top of the stage.** `src/app/App.tsx:270-288`; `src/engine/index.ts:41`. The tiles render only while the Style tab is open, so typing is not affected. On a phone, rapid Shuffles may lag, though I did not measure it. Fix: measure the time on a phone in R7, which already times exports. If it is slow, cancel the tile renders still waiting when the next Shuffle arrives, as the `stop` flag already allows, and start them after a 150 ms delay.

**M8. "Copied" shows even when the clipboard write fails or is missing.** `src/app/App.tsx:194-196`. Fix: flash "Copied" in the `then`, and in the `catch` show the seed selected or flash "Copy failed".

**M9. `.field` declares `min-height: 44px`.** `src/app/app.css:65`. That is under the 48 px rule. It passes only because `height: 100%` stretches the field. Fix: `min-height: 48px`.

**M10. Long-press on the Kept cells has no touch-callout guard.** `src/app/app.css:94`. On some phone browsers a long-press on a canvas can start selection or an image callout before the 600 ms delete fires. Fix: `.cell { -webkit-touch-callout: none; user-select: none; touch-action: manipulation; }`.

## Verdict

**Fix.** 0 errors, 7 should-fix, 10 minor. Every Done-when line is true in this workspace, and each "(tested)" line has a test that would fail if the line were false. Spec 10.1 and 10.2 are covered, and the greyscale chrome is the right reading of the spec against the refs. The fixes are: Finish and Marks controls that do nothing before R7; the `?s=` link discarding the saved design; silent storage failure; Kept truncation keeping the oldest designs; hardcoded panel pages at 412 x 915; reroll labels that duplicate the locks; and a layout check blind to panel spill.
