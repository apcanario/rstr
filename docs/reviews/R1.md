## Error

**E1. A picked Vaporwave layout makes a fallback that fails 9.2.**
- File: `src/engine/styles/vapor.ts:26-28` and `src/engine/layout.ts:73`.
- Failure: the fallback (k = -1) still obeys `spec.pick.layout`. With `pick.layout = "title-sky"` at 1:1, 100 of 100 seed sets fell back, and 42 of those fallbacks fail rule 4. Example: seeds `{layout:100, colour:54, graphic:44, type:3}` gives `title.chrome contrast 1.25 < 3 (#FFFFFF on #FFE66D)` (the sun behind the title). At 3:4, 1 of 100 fails. Spec 4 says the fallback "must always pass", and spec 3 makes `pick` part of every spec. Swiss and Postmodern picks fall back 0 times in 100 per layout and format.
- Fix: the fallback ignores a picked layout that cannot pass and uses the style's safe frame (`title-floor` for Vaporwave), or `solve` checks the fallback and, if it fails, retries it with `pick.layout` cleared. Extend `proof.specs()` and the smoke run to cover every value of `pick.layout` and `pick.motif` for each style, so a picked spec is tested like a seeded one.

## Should-fix

**S1. Swiss and Postmodern refs drift because the shuffle was replaced; record it as a Choice.**
- File: `src/engine/graphics/swiss.ts:63`, `src/engine/styles/pomo.ts:34`.
- The builder's stated reason ("a seeded shuffle") is only half right. The spike's `a.sort(() => r() - 0.5)` also draws from the seeded stream. Put back into a scratch copy, it redrew all three refs exactly, including the red block that `swiss-blocks-9x16`'s own subtitle names ("one red"). But it is not reproducible in Chrome. In the same page, the same seed gives different comparator call counts from one evaluation to the next (4 vs 5 and 28 vs 40 calls). With it, the smoke run's 9.3 pomo check failed in about 1 run in 3 ("colour moved a box", "type moved a graphic"). Fisher-Yates is the right call, because spec 3 (same spec, same design) outranks matching the refs seed for seed. A plain-JS copy of V8's binary-insertion path matched 2 of the 3 refs and missed `pomo-9x16`, so the drift cannot be fixed reliably.
- Fix: keep Fisher-Yates. The changelog Choices line must say that `swiss-blocks-9x16` now shows one black block and no red, and that both Postmodern refs place different shapes. The style's character holds, but they are not the same designs. Pedro vetoes.

**S2. Vaporwave titles leave the sky because every candidate must pass for every palette.**
- File: `src/engine/layout.ts:61-70`.
- Failure: `vapor-3x4` (c2) and `vapor-9x16` (c1) reject candidate 0, which has the title in the sky as in the refs. The rejection does not come from Miami, the palette in use. It comes from Night (`#FFFFFF on #FFE66D`): over a dark sky and a yellow sun, neither white nor dark ink passes. Adding the sun's colours to `inkFor` (tried in a scratch copy) changes nothing. The all-palettes rule is a sound way to meet 9.3, but it ties every layout to the worst palette of the style. With 8 palettes per style (R2) and saved palettes (R11), more candidates will be rejected for colours the design does not use.
- Fix: record it as a Choice (Vaporwave sky titles over the sun are rejected while any palette of the style cannot carry them). Put a line in Carried for R9: a sky-title treatment that passes for every palette, such as a dark plate band or a wider outline, so the spike's sky layout comes back. Also have `inkFor` (`vapor.ts:45-48`) include the sun's colours when the box overlaps the sun, so the ink choice matches what `behind()` checks.

**S3. 9.2 runs about 22 seed sets per text variant, not 200.**
- File: `src/engine/proof.ts:40-41`.
- Failure: `specs()` cycles the 9 text variants over the 200 seeds, so each variant (1, 3 and 8 word titles, every slot on, each slot alone) gets about 22 seed sets per style, format and mode. Spec 9.2 asks for 200 seed sets with each text.
- Fix: loop variants inside seeds (200 x 9 per style x format x mode, about 43 200 solves; the smoke run's engine checks take 7 s for 4 800, so about a minute). Keep the unit test on a smaller n.

**S4. Rule 4 checks only the colours a style declares as `ink`.**
- File: `src/engine/invariants.ts:26-30` and `:48-53`; `src/engine/styles/vapor.ts:62`.
- Failure: the Vaporwave title declares only its outline (`ink: [tInk]`, about 2.2% of the size wide), so the chrome gradient fill is never checked. On the Mint floor (#F6EBFF) the white stop of the fill is about 1.1:1. `behind()` also skips the text item's own echoes, and the outline sits on the accent and accent2 echoes along its offset edges (Night: white on #05FFA1 is about 1.3:1). The checker passes whatever a style claims, so 9.2 rule 4 is partly the style author's opinion.
- Fix: either `check` derives the ink from `fill` (the stops of a gradient) and `stroke` itself, and adds `echoes[].paint` to the background, or the outline-as-ink reading is written in the changelog Choices with a minimum outline width (for example 4% of size) that `check` enforces. Then test it in the checker's unit tests with an item whose fill fails and whose outline passes.

**S5. Export does not wait for fonts.**
- File: `src/app/App.tsx:40-42`.
- Failure: the Export button calls `render` straight away. A tap before `ready` resolves lays out and draws with fallback system fonts. Spec 4 says "after fonts are loaded" and spec 6 says "Export waits for fonts the same way".
- Fix: `await ready` in `save` (or disable Export until `loaded`).

**S6. The Paper accent was changed from #E4002B to #D10028.**
- File: `src/data/palettes/swiss.ts:4`.
- Paper's accent is the approved Swiss red and fills every Paper graphic. The change only gets red info labels to 4.5:1 (#E4002B on #F2EFE8 is 4.22). `firstInk([accent, ink], ...)` in `styles/swiss.ts:78` already falls back to ink for those labels, so the change is not needed for legality. It also leaves two Swiss reds, because Cobalt's accent2 is still #E4002B.
- Fix: revert to #E4002B and let the labels go to ink. If the builder keeps #D10028, it must be a Choices line so Pedro can veto it.
- The Signal change (ink and accent2 #F7F4EE to #FFFFFF) is right: #F7F4EE on #E4002B is 4.41, below 4.5 for small text, and #FFFFFF is 4.85. Changing accent2 with it is consistent, because it stops a near-white fourth colour. Record it under Choices; nothing to change.

## Minor

- **M1. Knock-outs are trusted, not checked.** `src/engine/invariants.ts:23` skips any graphic whose `avoid` covers the text, on the promise that `paint` cuts the glyphs out (`paint.ts:285-305`). No pixel test proves it, and when `layer()` returns null `paint` draws the graphic without holes. Fix: in the smoke run, render a Vaporwave spec twice, with stars and grid in a marker colour, and assert that the marker colour never appears inside any text item's glyph mask.
- **M2. The 9.3 type-seed test proves nothing for three styles.** Swiss, Postmodern and Vaporwave have one pairing each, so changing the type seed cannot move anything (`proof.ts:79`). Fix: a unit test that adds a second stub pairing with different widths to each style and runs `runIndependence`. Otherwise the line becomes meaningful only in R3.
- **M3. Independence runs in light mode only** (`tests/proof.test.ts:45`, `tools/smoke.py:46`). Add dark mode once R2 makes it differ.
- **M4. Brutalist title lines do not fill the width in 1:1 Anton.** `src/engine/styles/brutal.ts:99`: when height binds, `kx < 1` shrinks the lines (sheet: 1:1 Klein and 1:1 Alarm leave about a third of the width empty). The port is faithful to the spike, but spec 8.3 says every line fills the full width and stretches vertically. Clumsy, legal: spec 8.3. Carry to R8.
- **M5. Swiss Cobalt shows two accents.** `src/engine/styles/swiss.ts:50` passes accent2 (#E4002B under a blue accent) to blocks, against spec 8.1 "one accent". From the spike. Carry to R2/R5.
- **M6. Vaporwave 1:1 crowds the caption under the subtitle** (sheet: 1:1 Mint c4 and c0). `vapor.ts:99` anchors the caption at `bot` whatever is above it. Clumsy, legal: spec 8.4. Carry to R9.
- **M7. Segment buttons have no side padding.** `src/app/app.css:13-14`: at 360 x 640, "Postmodern" runs edge to edge in its pill. The smoke overflow check uses padding (0), so it cannot see this. Fix: `padding: 0 8px` and size the 360 font to fit inside it. Spec 10.1.
- **M8. App chrome colour.** The coral wordmark letter, selected segments and Shuffle, plus the orange export icon (`app.css:103,110,113-114`), go against spec 10.1, "dark and quiet so the poster is the only colour on screen". Fine for a placeholder screen; R4 must follow `ui-*.jpg`.
- **M9. Canvas context outside the engine.** `src/api.ts:30` reads pixels with `getContext('2d').getImageData`. Move the pixel hash into `src/engine/` (CLAUDE.md: all drawing in `src/engine/`).
- **M10. One failed core font blocks the stage forever.** `src/fonts.ts:11` uses `Promise.all`, so a single failed core font means nothing ever renders. Use `allSettled` and draw with what loaded; R3 adds the note.
- **M11. Choices to record when closing the row** (none of these are in the builder's commit): Fisher-Yates in place of the spike's comparator sort (S1); the all-palettes candidate rule (S2); Signal and Paper colours (S6); the Brutalist accent line in dark ink.
