## Should-fix

**S1. Posterise can draw two colours; spec 8.9 says three to five.** `src/engine/treat.ts:123` (`const n = Math.max(2, Math.min(want, cs.length))`). Swiss `yellow` light has two distinct colours (probe 2). Swiss does not list posterise, but any treatment can be picked by hand (the tiles), so posterise there gives a two-colour threshold at 0.5. The test accepts it: `tests/treat.test.ts:108` (`toBeGreaterThanOrEqual(Math.min(3, pal.length))`). Fix: where the palette has fewer than three colours, posterise is not offered (the tile disabled, `treatOf` falling back to the style's favourite or to threshold, recorded as a choice). Then make line 108 demand `>= 3` for every form where posterise is drawn, plus a case for Swiss `yellow` light.

**S2. The smoke's determinism check never treats the photo twice.** `tools/smoke.py:401` (and `:373`) draws the same spec twice with `window.__rstr.pixels`. Both paints go through `drawPhoto` → `treatedBox` (`src/engine/paint.ts:187`), which returns the canvas kept from the first paint (`treated` map, key = params, colours, scale, box). So the second draw reuses the first one's treated pixels, and "the same spec and photo give identical pixels" (spec 9.3, 9.4) is not checked for the treated path in the browser (drawImage resampling + getImageData + treatment). Fix: export a cache clear from `paint.ts` (or pass `fresh`), expose it on `window.__rstr`, clear it between the two draws, and keep the comparison.

**S3. The 5.4:1 caption fade is held only over a photo.** `src/engine/pixels.ts:251`: `copierProof`, the copier-pass check without a photo, reads title words only (`if (it.slot !== 'title' ...) return`). The failure that made the builder change `CAPTION_FAINT` (`src/engine/parts/type/pomo-copy.ts:60`) is a caption on paper (probe 1). No test without a photo would catch a return to 4.6. Fix: read every text item in `copierProof` (at least the caption and its copies) with and without the pass, and fail on cells the pass takes under. Or add a unit or smoke case pinning the probe-1 spec (`pomo`, photocopy, seeds layout 6211 / colour 6203 / graphic 6303 / type 6403, `1:1`, dark; failing over a `test-landscape` column) with no photo, after first confirming it fails at 4.6 without the photo too.

**S4. The spec's key list and facet sentence do not name the new keys.** `docs/SPEC.md:387` lists the Advanced keys and their facets ("`g.*`, `graphics.*` and `vapor.*` Graphic's"). R15 adds `photo.duo`, `photo.contrast`, `photo.screen`, `photo.angle`, `photo.level`, `photo.levels`, `photo.dot` and `photo.treatment`, all Graphic's (`src/engine/controls.ts:99`). Withdrawing them on a style change (`src/app/state.ts:86`) is also new behaviour. Fix: add them to the key list and to the Graphic facet in 10.3. Say in 8.9 that a treatment picked by hand may be any of the seven, and that the per-style list governs only the graphic stream.

**S5. The Treatment tiles set their labels at three different sizes.** `src/app/App.tsx:584` (`chunk(..., 4)`). At 360 x 640 (`screen-360x640-adv-photo-2.png`, crop checked) "Threshold" is drawn visibly smaller than "Posterise", and both smaller than "Halftone" and "Duotone". "Duotone" and "Halftone" run to the tile edges. The smoke passes (no wrap, no overflow, 48 px), but the row reads as broken. Fix: three tiles to a row (Auto, Colour, Mono / Duotone, Halftone, Threshold / Posterise, Dither), or one fitted size per row (the smallest any label in the row needs). Recheck at 360 and 412.

## Minor

**M1. Swiss duotone often reads as monochrome (legal but clumsy).** `photo-treatments-ground.jpg` and `-box.jpg`, Swiss row, column 3: the duotone is a near-neutral grey to black, indistinguishable from the Mono cell beside it. Duotone is Swiss's favourite. The cause is `treatPairs` (`src/engine/treat.ts:62-70`), which offers every pair at 3:1 equally, including ground + ink, which in most Swiss palettes are both neutrals. Spec that makes it: 8.9 "duotone (two palette roles)" with no rule on which roles. Fix: for duotone, draw from pairs that include an accent first, and use ground + ink only where no accent pair reaches 3:1. Pedro's eye decides whether it matters.

**M2. The treated-box cache is too small for the Style tab, and nothing tests it.** `src/engine/paint.ts:177` (`TREATED_KEEP = 3`). The stage plus the four live style tiles make five treated boxes per Shuffle, each at full canvas size (`thumb` renders full size, `src/engine/index.ts:42`). Each Shuffle re-treats all five, and the finish's second pass re-treats again where its entry was evicted. Halftone is 147 ms per box in headless Chrome on this machine. Fix: keep at least 6 entries, add a unit test that a second paint of the same Scene does not call `treatPixels` again, and add to By hand H5: Shuffle on the Style tab with a photo in Halftone and say whether it lags.

**M3. The recorded "whole render" leaves the treatment out.** `src/engine/pixels.ts:439` (`treatBench`): `render` is timed after the first of five runs has filled the cache, so it is the render with the treated box reused (12 to 17 ms). A first render or an export pays `ms` + `render`. Fix: time the render with the cache cleared (or report `ms + render` as the first-render figure). The changelog should record the treatment times as printed (colour 32, mono 40, duotone 42, halftone 147, threshold 43, posterise 51, dither 47 ms, box 1080 x 1920, headless Chrome, median of 5).

**M4. Postmodern's style-level list is never read.** `src/engine/parts/graphics/pomo.ts:65`: `compose5` (`src/engine/styles/compose.ts:37`) uses the dialect's list whenever `plan.dialect` is set, and every Postmodern plan has a dialect. Fix: drop the style-level list for Postmodern, or say in a comment when it is used (a mix part in R18). Add a test that a Postmodern scene's treatment is always in its dialect's list (the existing test at `tests/treat.test.ts:153` checks pinned dialects only, not the unpinned stream).

**M5. Brutalist's list leaves out colour and includes mono.** `src/engine/parts/graphics/brutal.ts:144`. Mono draws greys that are not palette colours, in a style whose spec (8.3) is two colours and one accent, while full colour is excluded. That may be the intent ("hard two-tone pictures"), but it is a taste call. Record it under Choices so Pedro can veto, or swap mono for colour.

**M6. Mono and duotone ranges under text have no slack for the grid read.** `src/engine/treat.ts:179-185`: `treatedRange` widens only threshold and posterise by `TONE_SLACK`. Mono at contrast up to 1.8 stretches any error of the smaller grid copy by up to 1.8x. Smoke found no failure (378 items over a treated photo), but the measured path is taken rarely (8 of 246 measured in the R14 loop). Fix: scale `MEASURE_MARGIN` by the mono contrast, or widen the mono range by `TONE_SLACK * contrast`. Add a unit case with contrast 1.8.

**M7. In Simple, Auto does not say which treatment is drawn.** `src/app/App.tsx:584-590`: with Auto lit, nothing shows what the graphic stream picked. Spec 10.3's stepper "shows what the design draws while it is unset", and the Advanced controls do (`treatmentControl(String(P.treat))`), but the tiles are filtered out of the generated list (`App.tsx:617`). Fix: mark the drawn tile with a secondary state (outline or dot) while Auto is on.

**M8. Close-of-row items the builder's commit leaves to the main chat.** `docs/BACKLOG.md` (R15 to Done; remove Carried "R15 (from R14)", now cleared by `photoCopier`), `docs/CHANGELOG.md` (the treatment times, the caption-fade change and why, the snapshot hash change, the Choices: style lists and favourites, `photo.*` in Graphic's facet, any treatment by hand, halftone light-on-dark in dark mode, posterise per S1), and `README.md` "What it does today" and "Status" (photo treatments). Not a builder defect under RUN.md 4, but required before push.
